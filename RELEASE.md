# Betelgeuse v2.0 — нотатки релізу

**Дата:** 2026-10-24 · **Протокол MC:** v15 · **Unity:** 6000.x URP

## Головне

- **Нейромережу навчено правильно.** MLP 5→8→2 навчається офлайн еволюційною стратегією ES(1+λ), λ = 12,
  300 поколінь. Кожне покоління оцінюється на міні-батчі з 40 рандомізованих сценаріїв, найкраща
  політика обирається за окремою валідаційною вибіркою з 200 сценаріїв. Навчальні, валідаційні й тестові
  seed не перетинаються. Для Neural і Hybrid навчено окремі ваги (`BestWeights_Neural.json`, `BestWeights_Hybrid.json`)
  та журнали навчання (`*_training_log.csv`).
- **Одне ядро симуляції** (`LandingSimulation`) для гри, Monte-Carlo, навчання і headless-стенда.
- **Monte-Carlo у фонових потоках:** 100 запусків × 4 алгоритми за ~1–2 с; результат не залежить від кількості потоків.

## Виправлені помилки логіки

| Було | Стало |
|------|-------|
| MLP у порівнянні мала вручну задані ваги (`InstallIdealWeights`); «ES(1+1)» оцінював ваги за однією посадкою, λ лише масштабував σ | Офлайн ES(1+λ) на батчах сценаріїв з валідацією; у польоті та MC ваги заморожені |
| Навігація: акселерометр «вирівнював» оцінку крену по вектору тяги — при шумі сенсорів реальний нахил 8° сприймався як вертикаль | Орієнтація — інтегрування гіроскопа; акселерометр використовується лише для швидкості |
| Помилки pitch/yaw через `SignedAngle` давали повний кут на обидві осі; дві різні конвенції знаків TVC | Помилка відносно бажаної осі, розкладена по осях корпусу; одна конвенція для A–D |
| Бічне наведення перезаписувало кути TVC алгоритмів (gimbal-закони A–D фактично не працювали вище 35 м) | Каскад: спільне наведення задає бажану вісь корпусу, алгоритм відпрацьовує її своїм законом |
| Режим Ideal змінював фізику (вимикав інерційність TVC і дроселя, пориви вітру) і коефіцієнти законів | Ideal змінює лише умови (ПУ без збурень); модель і закони ті самі |
| Бічне підсилення різне для алгоритмів (PID 0.62 … Hybrid 1.2) — підгонка результату | Однакове спільне наведення; змінювати масштаб може лише навчена MLP |
| PID: стрибок похідної на першому такті; D-канал по похідній уставки (шум) | Без стрибка; D орієнтації — з гіроскопа, D тяги — з фільтром |
| Фаза Stack (підйом пакета) у коді, хоча завжди вимкнена | Видалено |
| Неявний розкид точки входу як функція вітру; повзунок «прискорення MC» без змісту | Явний повзунок «Розкид точки входу ±м» |

## Перевірка

- Тести Unity 6000.4.8f1 (batchmode): **EditMode 98/98**, **PlayMode 6/6**, зокрема димовий тест повної сцени
  (bootstrap → посадка → Monte-Carlo з експортом) і регресія навчених ваг (≥ 95 % у протоколі v15).
- `Tools\HeadlessSim\run.cmd selftest` — ключові інваріанти без Unity.
